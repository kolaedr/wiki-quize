# Етап 2 — Платформа (UGC + кабінет + модерація + retention)

**Мета:** будь-який зареєстрований користувач створює гру через візард; зручна рев'ю-черга; гість конвертується в акаунт без втрати прогресу; daily challenge; retention-фічі (колекції, колода помилок, челендж-лінк); українська мова.

## 2.1. Гість → реєстрація

- [ ] Prompt на екрані результату після першої завершеної гри («зберігай / ділись / створюй») — закривається, не повторюється
- [ ] Міграція локальних результатів (localStorage → акаунт) при реєстрації
- [ ] Шеринг результату (OG-картинка або текстовий блок а-ля Wordle)

## 2.2. Кабінет користувача

- [ ] Вкладка «Мій прогрес»: результати, стріки, daily-історія, улюблені
- [ ] Вкладка «Мої ігри»: статуси (`draft → pending_review → unlisted/published`), звіт валідації теми, причина відхилення, дії (стиль, перегляд/виключення сутностей, подати на рев'ю)

## 2.3. Візард створення гри

- [ ] Крок «Тема»: обрати існуючу або нова → пошук класу Wikidata (`wbsearchentities` автокомпліт) / пресет → імпорт → звіт валідації
- [ ] Крок «Механіка»: тільки розблоковані для теми + напрямок питання
- [ ] Крок «Конфіг і стиль»: назва, складність, кольори/обкладинка, розмір колоди в межах лімітів
- [ ] Крок «Прев'ю»: зіграти самому → submit (`pending_review`, доступна як `unlisted` за лінком)
- [ ] Творець не редагує факти: тільки excluded-сутності і подача

## 2.4. Ліміти проти сміття

- [ ] Enforcement з таблиці `limits`: колода 7–20, мін. розмір теми під механіку (choice ≥40, swipe/HL ≥30, timeline ≥50), макс 5000, 3 теми / 10 ігор на творця, 3 у рев'ю, 5 імпортів/добу
- [ ] Блок дублікатів тема+механіка+напрямок → пропозиція існуючої гри
- [ ] Редагування лімітів в адмінці

## 2.5. Рев'ю-черга (адмінка)

- [ ] Екран черги: одна сторінка на гру — вбудоване ігрове прев'ю, звіт валідації, семпл 20 випадкових карток списком, історія творця
- [ ] Дії: Approve / Keep unlisted / Reject з шаблонними причинами → причина в кабінет творця
- [ ] Логіка «тема вже перевірена → гра майже автоаппрув»

## 2.6. Скарги

- [ ] Кнопка «поскаржитись» на картці → `reports` (dedupe по браузеру/юзеру)
- [ ] N скарг на сутність → авто-excluded до розгляду
- [ ] Екран скарг в адмінці: resolve / виключити сутність / ігнор

## 2.7. Daily challenge

- [ ] Seed від дати (UTC), однакова колода глобально; окремий екран і стрік
- [ ] Шеринг результату; розподіл «ти кращий за X%» (агрегація по `sessions`)

## 2.8. Нові механіки і модифікатори

- [ ] **timeline-ribbon**: стрічка часу зі слотами; тап на слот → варіанти сутностей; анімація постановки; дистрактори за близькістю дат, мін. розрив ≥ 5 років
- [ ] **odd-one-out («зайвий у ряду»)**: грід 4 (2×2) або колонка з 3; **зайвого викидаєш свайпом** з гріда; генерація: 3 сутності спільної ознаки + 1 з іншого класу/континенту/століття
- [ ] **Модифікатор blur-reveal**: картинка від блюру до чіткості з **намальованим таймером** (countdown-кільце); раніше відповів = більше очок; вмикається в конфігу гри для будь-якої image-механіки
- [ ] Модифікатор blitz (таймер без блюру) — з того самого коду таймера

## 2.9. Retention-фічі

- [ ] **Колекції**: відгадана сутність «відкривається» в особистий альбом, прогрес по темі («Прапори 62/195»), відкриті записи з лінком на вікі; агрегат по sessions.answers
- [ ] **Колода помилок**: картки з помилками повертаються через 1 день / 1 тиждень окремою колодою «Повтори» (простий spaced repetition)
- [ ] **Челендж-лінк**: після гри «кинь виклик» → токен (`challenge_id`: game + seed + результат автора) → друг грає ту саму колоду → екран порівняння; таблиця challenges (token, game_id, seed, author_result, created_at)
- [ ] **«Цього дня»**: автогенерована щоденна колода з дат Wikidata («події 22 липня»), без кураторства; окрема плитка на головній
- [ ] **Телеметрія якості карток**: агрегат правильності по картці; ~50% (вгадують навмання) або ~99% (тривіально) → авто-флаг у чергу адміна

## 2.10. Українська мова

- [ ] `templates/uk.json` (шаблони під відмінки, не дослівний переклад), UI-переклад
- [ ] Активація вимоги uk-лейблів в інджесті; ресинк тем; метрика покриття в звіті

## Вихід етапу

Користувач реєструється після першої гри, створює у візарді «Картини Ренесансу: хто автор?», ділиться unlisted-лінком, адмін аппрувить за хвилину, гра в каталозі. Daily грається глобально. Все — EN + UA.
