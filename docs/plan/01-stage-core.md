# Етап 1 — Ядро (без UGC)

**Мета:** наскрізна вертикаль — теми «Країни» і «Автобренди» імпортуються в БД, п'ять стартових ігор граються на телефоні без скролів як PWA. Плюс swipe-binary і higher-lower, EN-мова, мінімальна адмінка.

**Стартові ігри (запуск каталогу):**

1. Прапор ↔ Країна
2. Герб → Країна
3. Мова ↔ Країна
4. Автобренд ↔ Логотип
5. Автобренд → Країна походження

## 1.1. Скаффолд і інфраструктура

- [x] Next.js (App Router, TS, Tailwind) + деплой на Vercel з першого дня
- [x] Neon Postgres через Vercel Marketplace, env-и в проєкті
- [x] Drizzle + drizzle-kit: конфіг, перша міграція, npm-скрипти (`db:generate`, `db:migrate`, `db:studio`)
- [x] Better Auth: email+password + Google OAuth, таблиці в нашій БД, ролі `user|admin`
- [x] Auth UI: сторінка `/auth` (вхід/реєстрація, Google опційно через `NEXT_PUBLIC_AUTH_GOOGLE`), кнопка акаунта/виходу в хедері
- [x] Базовий layout: `100dvh` app-shell, safe-area, next-intl (EN)
- [x] PWA: manifest + іконка
- [x] PWA: service worker (`public/sw.js`: cache-first статика, network-first сторінки з фолбеком)

## 1.2. Схема БД

- [x] Таблиці: `topics`, `topic_entities`, `games`, `sessions`, `import_jobs`, `limits`, `challenges` (+ auth-таблиці Better Auth); всі текстові поля — jsonb per-locale
- [x] Типи TS зі схеми
- [x] Сід-скрипт **`npm run db:seed`**: дефолтні `limits` + рукописні дані (38 країн, 26 автобрендів з лейблами EN/UK, мовами, населенням, площею) + **усі 7 стартових ігор** — для відточування дизайну без живого імпорту; ідемпотентний, живий імпорт його перезаписує

## 1.4. Механіки і колоди

- [x] Типи `ChoiceCard`/`DeckEntity`/`BuildChoiceOptions` (`src/lib/deck/types.ts`)
- [x] Server-side `buildChoiceDeck(seed)`: seeded RNG (mulberry32), дистрактори-сусіди за складністю, ramp легкі→складні (`src/lib/deck/build.ts`)
- [x] **Правило мультизначності**: `answerKeys` — дистрактор не може ділити жоден ключ відповіді з питанням
- [x] Механіка `choice` з ДВОМА лейаутами: **duel** (пара гральних карт «в руці», нахилені з перекриттям; тач → свайп у бік відповіді, миша → hover+клік) і **quad** (промпт + 2×2 тапи); emoji-фолбек картинок
- [x] Лейаут — **глобальне налаштування юзера** (zustand persist у localStorage, перемикач ⚔️/🎯 в хедері гри; міграція в акаунт — етап 2), одна гра = кілька відображень
- [x] Input-aware ввід: `(pointer: coarse)` → drag-шар, інакше клік/hover/клавіші
- [x] Підключити ігри до БД: `/play/[slug]/[level]` будує колоди з `topic_entities` за механікою гри (`from-db.ts`), імпорт автостворює published-ігри пресетів (7 шт.)
- [x] **Relation-ігри** (`buildRefChoiceDeck`): «Мова і країна», «Звідки бренд авто» — відповідь = пов'язана сутність `{qid, labels}`; працюють на сідах
- [ ] Enrichment-прохід у живому інджесті: конвертувати QID-масиви P37/P495 у `{qid, labels}` (друга SPARQL-вибірка лейблів) — до того relation-ігри наповнюються тільки сідами
- [x] `swipe-binary` («Правда чи ні»): одна картка-твердження, свайп праворуч = правда, ліворуч = ні; бейджі вердикту при драгу, кнопки ✗/✓ для миші; шаблони тверджень через i18n (`game.tmpl.*`), генерація з числових пар з розривом ≥15%, правдивість перевірена тестом
- [x] `higher-lower` («Більше: населення»): шаблонне питання + дуель-пара карток, рендериться SwipeDuelBoard
- [x] Шаблони питань — через i18n messages (`game.tmpl.*`, EN+UK), сервер віддає ключ+параметри, клієнт рендерить локаллю

## Вихід етапу

Прод на Vercel: гість ставить PWA на телефон, відкриває каталог і грає всі 5 стартових ігор (прапори, герби, мови, автолого, країни-виробники) англійською, без скролів; бонусом «правда/брехня» і «більше/менше» на тих самих темах. Адмін імпортує нову тему пресетом і збирає з неї гру формою.
